## 二、UI 与交互架构

- **UI 引擎**：Jetpack Compose（Compose BOM `2026.03.01`），无 XML / Fragment。
- **设计规范**：Material Design 3，搭配专属调色盘（`YanjiTheme`）。
- **统一设计系统基元**（`ui/components/`）：
  - `YanjiPageHeader`：大标题 + 副标题标准化页面顶栏
  - `YanjiDetailTopBar`：标准化带返回键与标题的子页顶栏
  - `YanjiCard`：统一样式与圆角的容器卡片
  - `YanjiPrimaryButton` / `YanjiSecondaryButton`：主行动与次级操作按钮
  - `YanjiTextField`：统一样式的输入控件
  - `YanjiMetric`：标准化 52px / 36px 关键数据指标排版
  - `YanjiChip`：胶囊状态与筛选标签
- **大文件模块化拆分**：主界面及子页面（`ExamScreen`, `FocusScreen`, `StatsScreen`, `JuanjuanChatScreen`, `ProfileScreen`）均拆分为核心 Screen、Content 布局、独立子组件与弹窗文件，每个文件维持在 300 行以内。
- **页面路由与进程恢复**：
  - 自定义堆栈式导航（`Navigation.kt`）支持全屏子界面层叠。
  - `YanjiSubScreen` 声明 `@Serializable`，通过 `YanjiSubScreenStackSaver` 与 `rememberSaveable` 绑定。
  - 经历 Activity 重建或系统杀进程（Process Death）后，子页面堆栈及参数实现无损恢复，由 `NavigationRecreationTest` 严格验证。
- **图标体系**：Phosphor Icons `1.0.0` + Material Icons Extended（统一使用 `AutoMirrored` 语义图标）。
- **Flow 采集**：全部使用 `collectAsStateWithLifecycle()`，UI 不可见时暂停订阅。

## 三、依赖注入体系 (DI)

### 纯 Kotlin `AppContainer`（Status: Implemented）

项目采用轻量、显式、纯 Kotlin 的应用级容器（`AppContainer` / `DefaultAppContainer`）配合 `LocalAppContainer` CompositionLocal 与 `yanjiViewModel` 工厂函数。

#### 为什么不引入 Hilt：
1. **轻量与单一模块**：研迹是紧凑的单 module 纯 Compose 本地优先应用，无复杂的跨 module 依赖图。
2. **构建速度保护**：Hilt 带来额外的 APT/KSP 编译开销、字节码注入与类加载代理，会显著拉长增量构建时间 30~50%。
3. **可测试性与透明度**：纯 Kotlin 容器零反射、零代码生成。在单元测试和 Compose 视口测试中，只需传入测试实例或 Fake，无需使用复杂的 `@UninstallModules` 或 TestRunner 注入。

## 四、数据持久化体系

- **引擎**：AndroidX Room **2.8.4** + SQLite。
- **当前 schema 版本：v11**（`YanjiDatabase`，`exportSchema = true`，Schemas 从 7 至 11 严格版本管理）。
- **迁移原则**：
  - 严格手写 `Migration`，**严禁使用 `fallbackToDestructiveMigration()`** —— 必须守护用户所有真实备考轨迹。
  - 迁移统一覆写 `migrate(connection: SQLiteConnection)`，采用兼容低版本 SQLite 的「创建新表 → 数据拷贝 → 替换重命名」规范。
- **v11 迁移特性**：
  - `journal_entries` 增加 `date` 唯一索引（`index_journal_entries_date`）。
  - 迁移时针对历史可能存在的重复日期记录，实施确定性去重：保留 `updatedAt DESC, createdAt DESC, id DESC` 的唯一记录，彻底消除因日期并发可能产生的数据冲突。
- **数据表与职责**：

| 表 | 职责 | 核心索引 |
| :--- | :--- | :--- |
| `focus_sessions` | 单次专注会话（科目、起止时间、有效秒数、暂停次数/时长、模式、备注、状态） | `startTime` |
| `exam_sessions` | 全真模考会话（计划/实际用时、得分、满分、复盘） | `startTime` |
| `journal_entries` | 每日复盘（心态/精力/满意度打分、正文、困难卡点、次日计划、标签） | `date` (UNIQUE) |
| `user_settings` | 目标院校专业、每日目标、有效时长阈值、**AI 非敏感配置**（不含 API Key） | — |
| `chat_sessions` / `chat_messages` | 卷卷多会话对话存档与消息流 | `sessionId`、`timestamp` |
| `check_ins` / `unlocked_achievements` | 打卡与成就解锁 | — |
| `quick_start_presets` | 首页快捷操作（内置模板 + 自定义组合） | `sortOrder` |

## 五、统计性能下沉 (Performance)

- **DAO 级下沉聚合**：`StudyStatisticsRepository` 的时间区间统计（`getFocusDurationBetween`、`getExamDurationBetween`、`getSubjectDurationBetween`）已全部下沉至 Room SQLite 查询（`SUM(durationSeconds)`、`GROUP BY subjectId`）。
- **时间复杂度降低**：从原有内存遍历全量历史会话的 $O(N)$ 降低至利用 `startTime` 索引的 $O(\text{区间数据量})$。
- **高吞吐性能验证**：通过 `StatsPerformanceTest` 在 20,000 条 Focus 记录与 5,000 条 Exam 记录（合计 25,000 条记录）的真实 SQLite 数据库上压测，查询均在 **< 10ms** 内完成，彻底杜绝主线程卡顿与掉帧。

## 六、安全与凭据管理 (Security)

- **AI API Key 不入库**：严格隔离于应用 Room 主数据库之外。
- **Fail-Closed 故障闭环**：
  - 彻底移除了原有明文 Base64 回退写入漏洞。
  - 若设备 Android Keystore 损坏或不可用，系统拒绝写入并向用户明确提示「安全存储不可用，Key 未保存」，绝不在磁盘上产生明文密钥。
- **历史明文安全单向迁移**：
  - 历史明文文件仅在首次启动时解密并转入 Keystore 加密文件一次，迁移后立即彻底粉碎删除原明文文件。
- **备份与还原边界**：
  - 活动计时快照与 API Key 凭据存放于 `context.noBackupFilesDir`。
  - 系统 Cloud/Device Backup 策略配置严格屏蔽该目录，换机或备份还原时绝不泄露个人秘钥。

## 七、长时计时器与进程死亡恢复 (Timer & Recovery)

- **单调时钟守护**：使用 `SystemClock.elapsedRealtime`，避免用户修改系统时间导致计时跳变。
- **活动会话实时落盘**：`FileTimerSessionPersistence` 将当前进行中的专注/模考状态序列化存入 `noBackupFilesDir` 下的原子快照文件。
- **跨进程死亡恢复**：在 Service 重启或应用进程被系统回收后，`ActiveSessionCoordinator` 启动时自动重新加载未完结的快照并恢复计时，不丢状态。
- **一致性事务保护**：计时完成在写入 Room 主数据库成功后才清理活动快照；若写入数据库出现异常，活动会话状态不丢失，防止崩溃丢数据。
- **互斥性保障**：同一时刻全进程严格限制仅允许 1 个活动计时会话。

## 八、AI 聊天体系 (Juanjuan Chat)

- **强类型错误模型**：定义 `AiFailure` 密封类（`ApiKeyMissing`, `NetworkError`, `HttpError`, `RateLimitExceeded`, `InvalidResponse`, `Unknown`），包含用户可读文案及是否可重试标志。
- **重试不重发**：用户点击「重试」直接复用上次已存库的尾部消息，不重复插入重复的用户消息。
- **会话隔离**：生成中状态（`AiReplyState`）以 `currentSessionId` 为边界，切换会话时自动隔绝，防止不同对话间串消息。
- **受限分页**：支持游标分页（`PAGE_SIZE = 30`），避免长对话导致内存暴涨。
