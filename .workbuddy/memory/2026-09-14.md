## 踩坑与新事实（重要）

- **本机模拟器镜像坏了**：`system-images/android-35/google_apis/x86_64` 里 **`system.img` 与
  `vendor.img` 缺失**（只有 kernel/ramdisk），emulator 报
  `No initial system image for this configuration!`，AVD `DiaryPhone` 起不来。
  `sdkmanager --install` 会因目录里还留着 `package.xml` 而**认为已安装、不重下**；
  必须先把该目录**移出 SDK 根**（放 `Sdk/_quarantine_*` 仍会被扫到，要放到 `C:/Users/dex/` 下）
  再重下（约 3.5 GB）。修复后 WHPX 加速可用，API 35 模拟器正常。
- **`git worktree remove` 在 Windows 上会因 Gradle build 目录长路径失败**
  （`failed to delete ...: Filename too long`），但**worktree 注册已被摘掉**；
  残留目录用 python `shutil.rmtree` 加 `\\?\` 前缀**也不行**，得用 PowerShell
  `Remove-Item -Recurse -Force`。本次残留 `build/verify-wt`（215 MB）未清干净。
- **并发编辑风险（本轮最大教训）**：会话进行中有**另一个进程在持续改写整个仓库**
  （成就系统 V2 重构，每 7~15 秒改一个文件：theme → components → navigation → screens），
  导致工作区反复不可编译：
  - `MainActivity.kt` 被删掉 `override fun onCreate` 与 `requestPermissionLauncher`，
    函数体裸露在类体里 → 语法错误；
  - `AchievementsScreen.kt` / `HomeScreen.kt` 删了 `androidx.compose.material.icons.*` 导入
    但 `Icons.Default.X` 用法还在 → `Unresolved reference 'Icons'`。
  → **结论：在同一仓库上并行跑两个改造任务会让验证彻底不可靠。**
    今后遇到这种情况，一律用 `git worktree add` 拉隔离副本验证，不要在活动工作区里反复构建。
- 修复动作与备份：被外部改坏的 `MainActivity.kt` 备份在 `build/wip-backups/`，
  工作区里已临时恢复为 HEAD 版本（可编译）；验证证据在 `build/verification/`。
