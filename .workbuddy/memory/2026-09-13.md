### 关键工程决策

- **语义状态与展示镜像分离**：`liveState`（仅 START/PAUSE/RESUME/FINISH/DISCARD 发射）
  给通知层；`elapsedSecondsForUi`（每秒）只给 Compose。两者同源于 TimerMachine，
  不是第二套计时器。这样通知层物理上不可能每秒 notify。
- **Compose 重组收敛**：`ActiveFocusContent(elapsedSeconds: State<Long>)`，在函数体内不读取，
  只在 `CountdownFocusBody` / `FlowFocusBody` 两个叶子读取 → 外层手工定位的 `Layout`
  不再每秒重组测量。`FocusScreen` 同理只转发 State 不取值。
- 保留 `TimerState`/`timerState` 仅供 `ExamScreen`（模考路径未在本次范围内）。

### 踩坑

1. **Service 字段初始化时不能取 `applicationContext`**：Android 组件「先构造、后 attachBaseContext」，
   字段初始化阶段 `applicationContext == null` → 启动即 NPE。改为 `lateinit` + `onCreate` 赋值。
   这是本次唯一一个会导致启动崩溃的问题。
2. **lint MissingPermission 不认 `runCatching`**：`NotificationManagerCompat.notify()` 需要
   显式 `try/catch (SecurityException)` 或 `@SuppressLint`。用显式 try/catch + `areNotificationsEnabled()`
   运行期守卫解决，不用抑制注解。
3. **`setVisibility` 只接受 `NotificationCompat.VISIBILITY_*`**，传 `Notification.VISIBILITY_PRIVATE`
   会触发 `WrongConstant`（取值相同也不行）。
4. **一条消息里的多个 Edit 会丢**：实测并行/连续发的两个 Edit 只落盘一个（本次发生 3 次：
   `CountdownFocusBody` 签名、`FocusNotificationSpec` 导入、插桩测试第 3 个用例）。
   **改多文件时一次只发一个 Edit 并回读验证**。

### 真机实证（OPPO PKB110 / ColorOS V16.1.0 / Android 16 / `ro.build.version.sdk_full=36.0`）

- **`NotificationManagerCompat.canPostPromotedNotifications() == false`**，
  而 `android.permission.POST_PROMOTED_NOTIFICATIONS: granted=true`、渠道 `mImportance=2`（LOW）、
  应用通知总开关为 true。→ 系统侧闸门关闭，**标准 Live Update 在当前 ROM 上不可用**，
  已按 §34 降级为「普通常驻通知 + 系统 Chronometer」。
- `dumpsys notification` 的 AppSettings 里本应用 `promoted=true`，但该字段**不等于**
  `canPostPromotedNotifications()`（`com.example.yanji.test` 同样是 true）——不要拿它当能力判据。
- ColorOS 自身的流体云门控设置键（`settings list secure`，可复核）：
  - `fluid_cloud_not_support=0`（本机支持流体云）
  - `fluid_function_request=1`、`fluid_settings_capsule_to_card=1`
  - `livealert_disable_seedling=com.application.zomato;`（泛在服务按包名denylist）
  - **`oplus_no_fluid_capsule_animation=com.android.incallui`（小胶囊动画按包名 denylist）**
    → 回答 §29/§30：胶囊动画是 ROM 侧按包名管控的，本应用不在禁列内。
- 真机插桩 16/16 通过（含被改签名的 `ActiveFocusContentInstrumentedTest`）。
- 真机渲染确认：倒计时 = 细环 + 无圆盘；暂停 = 状态点转橙 + 数字转次要色 + 呼吸收平；
  正向计时 = 无环、纯数字悬浮 + 极淡径向呼吸场；底栏隐藏。

### 踩坑

- **`./gradlew`（无扩展名）在本机报 `ClassNotFoundException: GradleWrapperMain`**，
  必须用 `./gradlew.bat`。根因是 Git Bash 下 MSYS 路径/git-bash 的 classpath 处理异常。
- **Kotlin daemon 会 sporadically 崩**（`e: Daemon compilation failed` +
  `IncrementalCachesManager.close` 文件锁），Gradle 自动 `Using fallback strategy: Compile without
  Kotlin daemon` 后仍 BUILD SUCCESSFUL。遇到 `e:` 先看有没有 `BUILD SUCCESSFUL` 收尾，
  别当成编译错误。多任务并发跑 Gradle 会加剧，建议 `./gradlew.bat --stop` 后串行。
- Gradle 输出含 NUL 字节，`grep` 会报 `Binary file (standard input) matches` → 先 `tr -d '\000'`。
