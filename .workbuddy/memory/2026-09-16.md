### 阻塞 1：依赖校验元数据覆盖不全（instrumented 图缺失）

- 失败点：`Dependency verification failed for configuration ':app:_internal-unified-test-platform-android-device-provider-ddmlib'`，
  缺失 `kotlinx-coroutines-bom-1.6.4.pom`。**instrumented job 才红，build job 一直绿**。
- 上一轮的做法是「每次 CI 报一个就手补一个 checksum」——每轮 ~11 分钟，不可持续。
- 真正根因（两个叠加）：
  1. 元数据是用**普通 build** 生成的，从不解析 AGP 内部的 UTP 配置（`_internal-unified-test-platform-*`）。
  2. **`--write-verification-metadata` 不会记录已在本地 Gradle 缓存里的 descriptor**——没有 `--refresh-dependencies`
     就永远补不上，文件会"看起来成功但依旧不全"。CI 冷缓存会重新下载 → 校验 → 报错。
- 解法（已提交）：`scripts/lib/resolve-all-configurations.init.gradle` 强制解析**所有**可解析配置
  + `scripts/regen-verification-metadata.sh` 包一层 `--refresh-dependencies`。脚本**只允许新增**：
  若重建会删改任何既有 checksum 就报错并还原原文件。
- 结果：584 components/972 artifacts → **590/981**（+9，0 删除）。9 个新 checksum **全部从 Maven Central
  独立重新下载并重算 sha256**：9 match / 0 mismatch。修复后 strict 模式整图 `--refresh-dependencies` 解析 BUILD SUCCESSFUL。
- 已知跳过项（**正常**）：`:app:debugUnitTestCompileClasspath` / `debugAndroidTestCompileClasspath`。
  Gradle 9 拒绝在 configuration 阶段解析 compile classpath（`IllegalResolutionException: ... without an exclusive lock`），
  是 Gradle 安全护栏；普通 build 会正常解析它们，CI 的 build job 一直绿即证明无缺口。

### 阻塞 2：真·flaky 单测

- `StudyStatsTest > durationSince only counts sessions starting at or after cutoff` →
  `expected:<4200> but was:<3600>`。**只有那一轮 CI 红，本地和之前多轮都绿**。
- 根因：`noonToday()` 设了 HOUR/MINUTE/SECOND 但**没设 MILLISECOND**，每次调用返回的瞬间都差几毫秒；
  测试分别调用两次 `noonDaysAgo(1)`（会话起点 & cutoff）再用 `>=` 比较 → 毫秒翻过去就少算 600。
- 量化（`build/FlakeProbe.java`，脱离 Gradle 跑 100 万次）：原逻辑 **398 次不匹配 = 0.0398%**；修好后 **0**。
- 修法：`set(Calendar.MILLISECOND, 0)` + cutoff 只算一次复用。断言语义（含等于 cutoff）不变。
