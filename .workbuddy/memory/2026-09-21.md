## 随笔编辑页顶栏「不透明」根因修复

- 用户真机反馈：随笔编辑页顶栏仍是白条，把正文挡住（截图显示首行文字被洗白）。
- **根因不是渐变参数，而是滚动视口被容器的 `padding(top=TopBarHeight-8dp)` 包在滚动之外**：
  正文永远进不了顶栏区域，滚到顶就被硬切 → 看起来像"导航栏挡住正文"。
  对比 `AiChatScreen`：LazyColumn 全屏，顶部让位用 `contentPadding`，消息能滚进顶栏区并被渐变淡出。
- 修法：
  1. 新增共享组件 `ui/components/TopFadeScrim.kt`（顶栏渐隐遮罩唯一实现，Chat / 随笔编辑页共用），
     顶端 alpha 从 0.96（几乎实色）降到 **0.32**，快速渐隐到全透明；调档只改文件内 `TOP_ALPHA`。
  2. `NoteEditorScreen` 两处让位（Edit / Preview）从容器 padding 移入滚动内容内部
     （`Spacer(editTopInset / previewTopInset)`，数值加回 statusBarHeight），视口改为从屏幕顶端开始。
  3. `AiChatScreen` 同步换用 `TopFadeScrim`，参数不再各写一份（消除漂移）。
- 验证：`assembleDebug` 成功；设计令牌守卫三项全绿；真机 `install -r` Success 并拉起主界面。

## 随笔历史页搜索栏与编辑页正文点击不弹输入法与光标丢失根因修复（同日第七轮）

- **问题**：
  1. 用户反馈历史页搜索栏与编辑页点击均未弹出软键盘；
  2. 且编辑页点击后甚至连光标都不显示了。
- **深入根因分析**：
  1. **光标消失根本原因**：
     - 在上一轮中，在 `NoteEditorScreen` 的 `decorationBox` 内部的 `Box` 上添加了 `.clickable(...)`；
     - 在 Compose 触摸事件分发树中，`decorationBox` 的 `Box.clickable` 处于父/包装层级，会优先且完整地消费（consume）所有的 pointer down/up 事件；
     - 导致包装在内的 `innerTextField()` 原生触摸手势链路被完全掐断，Compose 无法收到点击坐标，无法计算文本选择区（selection），光标彻底失去响应与闪烁！
     - 同理，外层 `verticalScroll` 的 `Box` 上挂载 `.clickable` 也会对子树点击产生手势竞争。
  2. **输入法不弹出的多重原因**：
     - **时序竞争（Timing issue）**：在 Compose 中通过 `focusRequester.requestFocus()` 请求焦点后，Android View 系统的 `InputConnection` 绑定是异步的（需下一帧）。在同一个同步调用栈内紧接着调 `keyboardController?.show()` 时，`InputConnection` 尚未建立，输入法管理器会判定为无效请求直接忽略；
     - **OEM 系统差异**：用户设备为 ColorOS（OPPO PKB110），默认输入法为微信键盘（`com.tencent.wetype`），对程序化 `show()` 极其严苛，在 `InputConnection` 未就绪或无直接触摸时容易静默压制；
     - **清单文件配置遗漏**：`AndroidManifest.xml` 中将 `android:windowSoftInputMode="adjustResize"` 错误地声明在 `<application>` 标签上，而该属性在 Android 规范中属于 `<activity>` 专属属性，导致 `MainActivity` 失去标准软键盘自适应调整模式。
- **终极修正**：
  1. `AndroidManifest.xml`：将 `android:windowSoftInputMode="adjustResize"` 正确移动至 `<activity android:name=".MainActivity">`；
  2. `NoteEditorScreen.kt`：
     - **彻底移除** `decorationBox` 容器与外层可滚动 `Box` 上的所有 `.clickable`，严禁拦截 `innerTextField()` 的原生手势，彻底恢复 Compose 原生文本选择与光标定位；
     - 在 `decorationBox` 的 `Box` 增加 `.defaultMinSize(minHeight = 120.dp)`，让短文本乃至空白笔记也有充分的直接点击触控面积；
     - 在文本下方的空白占位 `Box`（minHeight 500dp）处理留白点击，将光标定位至文末；
     - 引入协同唤起函数 `showKeyboard()`：通过协程 `yield()` 确保让出主线程一帧让 Compose `InputConnection` 彻底挂载就绪，并双保险调用 `keyboardController?.show()` 以及 Android 原生 `InputMethodManager.showSoftInput(view, InputMethodManager.SHOW_IMPLICIT)`。
  3. `NoteScreen.kt`（`NoteSearchBar`）：
     - 在 `focusSearch()` 与 `onFocusChanged` 中同样采用带 `yield()` 与 `InputMethodManager` 双保险的 `showKeyboard()` 流程，确保首次点击搜索栏胶囊时软键盘稳定弹出。
- **验证**：
  - 设计令牌守卫：`check-design-tokens.sh` 检查通过（Color 0, Radius 62, Theme 0）；
  - 单元测试：`gradlew.bat testDebugUnitTest` 26 项用例全部通过（10s）；
  - 编译构建：`gradlew.bat assembleDebug` 成功（4s）；
  - 真机推送：通过 mDNS 无线调试成功安装并拉起 `MainActivity`。

## 随笔编辑页满屏点击末尾文字跳转幅度不足与输入法/工具栏遮挡根因修复（同日第九轮）

- **问题**：用户反馈文字占满整个页面时，点击最下面的文字进行编辑，页面跳转（滚动）幅度不够，导致被底部工具栏和输入法遮挡，看不到要修改的地方。
- **根因分析**：
  1. **旧机制 `BringIntoViewRequester.bringIntoView()` 的天然局限**：Compose 原生 `bringIntoView` 只做"让目标矩形刚刚好蹭进视口边缘"的最小滚动，且当用户在软键盘未弹起前点击底部文字时，光标当时仍在满屏视口内，Compose 判定无需滚动；等 200ms 后键盘弹出，`selection` 未变，`bringIntoView` 不会再次触发，导致光标被键盘与工具栏完全覆盖；
  2. **视口尺寸未监听导致自定义滚动未能生效**：此前重构引入了 `editorViewportHeightPx`，但外层滚动 `Box` 尚未挂载 `.onGloballyPositioned`，导致 `editorViewportHeightPx` 始终为 0，`LaunchedEffect` 在第一行被 `editorViewportHeightPx <= 0` 拦截退出；
  3. **缺乏视口黄金阅读区计算**：没有将点击光标自动上移到视口黄金位置（约视口 40% 高度处），导致即使用户往上滑也紧贴底边。
- **修正**：
  1. **精准视口测量**：在 `NoteEditorScreen.kt` 的核心滚动 `Box` 上挂载 `.onGloballyPositioned { coordinates -> editorViewportHeightPx = coordinates.size.height }`，实时获取除去状态栏、底部工具栏与输入法后的净可视高度；
