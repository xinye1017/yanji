# 2026-09-15

## 修复：亮色/暗色模式下状态栏看不清（真机已复现并验证）

**现象**：App 冷启动后，状态栏区域恒为近白色 `#F7F9FC`，且状态栏图标为白色 → 时间/信号/电量完全不可见。亮色、暗色两种 App 主题下都如此。

**根因（两条独立缺陷叠加）**

1. `Navigation.kt` 根容器写死 `.background(YanjiBackground)`。
   `YanjiBackground` 是顶层 `val`（编译期常量 `Color(0xFFF7F9FC)`），不随主题变化；
   而内层内容用 `statusBarsPadding()` 下移，于是**状态栏与导航栏那条区域永远显示近白色**。
   —— 这正是用户看到的「纯白的背景」。
2. `MainActivity` 只调了无参 `enableEdgeToEdge()`。其默认 `statusBarStyle =
   SystemBarStyle.auto(TRANSPARENT, TRANSPARENT)`，`detectDarkMode` 默认实现是
   `(resources.configuration.uiMode and UI_MODE_NIGHT_MASK) == UI_MODE_NIGHT_YES`
   （已从 AndroidX 源码 `activity/activity/src/main/java/androidx/activity/EdgeToEdge.kt` 核实）
   ——**只跟随系统深色模式**，而本 App 主题由 `user_settings.themeMode` 决定、可显式覆盖系统。
   两者不一致时状态栏图标必然与底色同色。

**改动**

- 新增 `ui/SystemBarAppearance.kt`：`@Composable fun SystemBarAppearance(darkTheme: Boolean)`，
  用 `DisposableEffect(activity, view, darkTheme)` 写 `isAppearanceLightStatusBars /
  isAppearanceLightNavigationBars = !darkTheme`。用 key 控制只在主题变化时写一次，
  避免每帧重组覆盖专注页 `FocusSystemBarAppearance` 的临时反向设置。
- `MainActivity.kt`：解析 `darkTheme` 后调用 `SystemBarAppearance(darkTheme)`。
- `Navigation.kt:118`：`.background(YanjiBackground)` → `.background(MaterialTheme.colorScheme.background)`，删 import。
- `values/themes.xml` + 新增 `values-night/themes.xml`、`values/colors.xml`、
  `values-night/colors.xml`：`Theme.Yanji` 显式声明 `windowBackground` + `windowLightStatusBar` /
  `windowLightNavigationBar`，保证**启动窗口**（Compose 首帧之前）自身也有对比。

**真机验证**（OPPO PKB110 / ColorOS，按 `AGENT.md` 的 mDNS 单行链式流程）

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| App 暗色 | 白底 + 白图标，不可见 | `#0D111A` 底 + 白图标，清晰 |
| App 亮色 | —（同上恒白底） | `#F7F9FC` 底 + **深色**图标，清晰 |
| App 亮色 + 系统强制深色 | 必为白图标，不可见 | 深色图标，不受系统影响 |

证据截图：`build/yanji_before.png`（修复前）、`build/after_dark.png`、`build/light_app_system_auto.png`。
「App 亮色 + 系统深色」截图与「App 亮色 + 系统亮色」字节完全一致，证明系统模式不再影响本 App 的系统栏外观。

**遗留 / 待确认**

- 启动窗口只能跟随**系统**深色模式（`values-night`），无法跟随 App 内的显式选择：
  App 设 DARK 而系统 LIGHT 时，冷启动会有一帧亮色闪屏。若要消除，需把 `themeMode`
  额外镜像到 SharedPreferences，在 `super.onCreate()` 之前 `setTheme()`。当前未做。
- 验证过程中把 App 主题临时改成了「浅色」再还原为「跟随系统」；用户原本的档位无法反推。

## 真机推送最新版本，并修复 haze 导致的「启动即崩」

**任务**：把最新版本推送到 OPPO PKB110（API 36，无线调试）。结果：推送成功，但**过程中发现该版本存在阻断性崩溃**，一并修复。

**关键背景**：真机已装包是 **debug 签名**（`run-as` 可用反证），已装 `versionCode=1`，
数据库 `user_version = 12`，与代码 `@Database(version = 12)` 一致 → 本次覆盖安装**不触发任何迁移**。

**崩溃（阻断级，App 完全不可用）**

- 现象：启动即崩，进程反复重启（crash log 连续多条、PID 不断变化）。
- 异常：`java.lang.IllegalArgumentException: backgroundColor not specified. Please provide a color.`
  `at dev.chrisbanes.haze.BlurEffectKt.drawScaledContentLayer(BlurEffect.kt:146)` → `RenderEffectBlurEffect.drawEffect(BlurEffect.kt:102)`
- **重要**：崩溃早于本次安装。日志显示**自 21:58:52 起就持续崩溃**，即上一次安装（21:58:50）之后就从未成功启动过。
- 根因：haze 是当天 **20:55** 才引入的新依赖（提交 `9cc3835`），从未在真机验证。
  `GlassSurface.kt` 的 `hazeEffect` 只设了 `blurRadius/tints/noiseFactor`，**未设 `backgroundColor`**。
  haze 1.5.4 的 `RenderEffectBlurEffect.drawEffect()` 在 RenderEffect 路径（API 31+）下
  **无条件**调用 `drawScaledContentLayer`，该函数硬性 `require(bg.isSpecified)`；
  解析链 `node.backgroundColor → style.backgroundColor → compositionLocalStyle.backgroundColor`
  三级全空 → 抛异常。（已从 sources jar 逐行核实，非猜测）

**修复**：`GlassSurface.kt` 内 `backgroundColor = Color.Transparent`。
透明矩形在 SrcOver 下是 no-op，不改通透观感；着色仍由 `tints` 承担。
提交 `9f2262c fix(ui): 修复 haze 毛玻璃导致真机启动即崩溃`。
