### 关键工程结论（踩坑记录）

1. **迁移测试此前根本无法编译**。`YanjiMigrationTest` 用的是不存在的
   `MigrationTestHelper(file, dbName, ...)` 三参 API 与 `SupportSQLiteDatabase.query`。
   Room 2.8 的 JVM 版本真实签名是
   `MigrationTestHelper(schemaDirectoryPath, databasePath, driver, databaseClass, databaseFactory, specs)`，
   且 `runMigrationsAndValidate(version, migrations)` 返回 `androidx.sqlite.SQLiteConnection`。
   `databaseFactory` **会在构造时立刻被调用**，必须返回真实实例（`YanjiDatabase_Impl()`）。
2. **Room 2.8 的 Migration 必须覆写 `migrate(connection: SQLiteConnection)`**。
   Android 变体才有 `migrate(SupportSQLiteDatabase)`，且只在 connection 是
   `SupportSQLiteConnection` 时桥接；JVM 变体**只有** SQLiteConnection 版本。
   只覆写旧签名会导致「JVM 测试静默跳过迁移、真机却会执行」。
   已把 7 个迁移全部改写为 SQLiteConnection + `prepare().use { step() }`。
3. **`ALTER TABLE ... DROP COLUMN` 在 minSdk 24 真机上不可用**（需 SQLite ≥ 3.35）。
   `MIGRATION_3_4` 原来用它删 `isThinking`，已改为「建新表→拷贝→删旧表→改名」。
4. **单元测试类路径变体错配**：`room-testing-jvm` 针对 jvm 变体编译，而 Android 模块默认把
   `room-runtime` 解析成 android 变体，运行期抛
   `NoSuchMethodError: DatabaseConfiguration.<init>(...)`。
   在 `app/build.gradle.kts` 用 `configurations.configureEach { name.contains("UnitTest") }` +
   `dependencySubstitution` 把 test* 配置换成 `room-runtime-jvm` / `room-migration-jvm`。
   注意 AGP 9 的单元测试配置名是 `debugUnitTestRuntimeClasspath`，**不以 test 开头**。
5. **`app/schemas/.../7.json` 曾被 KSP 覆盖成新 schema**（改实体但版本号还是 7 的那次构建）。
   已临时回滚实体 + 版本号 7 重新导出一份正确的 v7（17469 字节，含 aiApiKey 与
   studyDurationSeconds），再恢复 v8（17055 字节）。**改实体时务必同步改 `@Database(version)`**。

### 本环境的 ADB 可靠用法（重要）

- **adb daemon 会随 Bash 子进程结束被重置**，跨命令调用会得到
  `no devices/emulators found`。所有 adb 操作必须链在同一次执行里。
  已写成脚本：`build/adb-backup.sh`（备份+状态）与 `build/adb-push.sh`（安装+启动+校验+日志）。
- **不需要问端口**：`adb devices` 会通过 mDNS 自动出现
  `adb-XXX._adb-tls-connect._tcp` 形式的设备（无线调试已开时）。用 `adb -s <该串>` 或
  单设备直接 `adb`。
- `adb connect <ip>:5555` 不成立（除非之前手动 `adb tcpip 5555` 过）。
- 备份用户数据：`adb exec-out run-as com.example.yanji cat databases/yanji_study.db`，
  **必须连 `-wal` / `-shm` 一起拉**，否则读到的是过期快照（本次 WAL 有 123KB 未落盘）。
- 备份产物在 `build/device-backup/`（before 是 v7、prev-v9/after 是 v9，含截图）。

- Repository 保留同名委托属性/方法，**JuanjuanChatScreen 一行都不用改**。
- 构造顺序约束：`chatStore` 依赖 `repoScope` / `aiClient` / `_settings`，必须声明在它们之后。

### 这轮踩的两个坑（都很贵，务必记住）

1. **脚本变量名 `TMP` 撞上 Windows 的 `TMP/TEMP` 环境变量**，adb server 起不来
   （报 `cannot open ...adb.log`）。变量改名后立刻恢复。以后写 adb 脚本别用 TMP/TEMP 当变量名。
2. **脚本 bug 差点造成数据丢失**：拉取时写到 `before-yanji_study.db`，
   但 Python 打开的是 `yanji_study.db`（`sqlite3.connect` 会**新建空库**），
   然后把这个空库推回设备，覆盖了真实数据。
   **靠"覆盖前几秒刚拉的完整快照（含 -wal）"救回来了**。
   教训：① adb 脚本必须 `set -euo pipefail`；② 对文件做写操作前必须断言
   `user_version` / 关键表存在；③ **永远先快照再动手**，这条救了命。

### 构造顺序约束（容易踩）

Repository 里各 Store 的声明顺序必须是：`repoScope`/`database` → 四个 Store → `chatStore`。

### 自动化脚本的坑（第四轮新增）

- 用 Python 花括号配对删除"无花括号体"的成员（如 `data class`）会**误删后续函数**——

  以后删除成员要么用精确文本匹配，要么删完立即编译。
- Python 脚本里 `os.makedirs` 要先于写文件执行（生成器脚本两次踩同一个坑）。
